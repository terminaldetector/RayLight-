# Half-Life: Abaddon · нативный полёт

Первый нативный срез использует игровые библиотеки Valve Source SDK 2013 Singleplayer. Он добавляет полёт с инерцией, набор высоты по локальной оси, крен и скольжение вдоль стен. Мышь вращает взгляд относительно корпуса. Столкновения проверяет обычный вертикальный корпус игрока. [Журнал сборки](BUILD_RESULTS_RU.txt)

Управление подключается после команды `abaddon_flight`. Повторная команда возвращает обычное движение, оружие и ровную камеру. При гибели, появлении, загрузке сохранения, входе в транспорт или захвате управления стационарным объектом режим выключается.

Разгон ограничен 4200 SU/с², скорость — 2200 SU/с. При отпускании тяги скорость постепенно гасится. Модуль одинаково применяется в расчёте движения на сервере и клиенте. Сетевой флаг режима передаётся штатной таблицей `DT_HL2_Player`, а поворот подаётся через обычный `CUserCmd`.

## Боевой полигон

Четыре независимых крепления используют общий испытательный режим «Пульсар». Они могут выстрелить в одном такте. Сервер ведёт отдельные интервалы по 0,06 с для каждого крепления и чередует два физических дула. Переключение полёта сохраняет очередь дул и время следующего выстрела. Новая жизнь или загрузка сохранения начинают новую очередь.

Дуло следует за креном и смещением корпуса. Сервер проверяет путь от центра корпуса через крепление к дулу, затем трассирует сам выстрел. Преграда перед дулом подавляет выстрел. Попадание, трассер и вспышка исходят из одной серверной траектории. В полёте команды стрельбы обрабатывают крепления, даже если у пилота пустые руки. Пилот вне полёта использует обычное оружие HL2.

| Крепление | Действие Source | Клавиша |
|---|---|---|
| Левое | `+attack` | Основная атака |
| Правое | `+attack2` | Дополнительная атака |
| Верхнее | `+grenade1` | Например, `bind j +grenade1` |
| Нижнее | `+grenade2` | Например, `bind k +grenade2` |

Этот этап проверяет управление креплениями и попадания лучевой трассой. Модели корабля и кокпита, смена классов, полноценные летящие снаряды, боезапасы, мины, саппорты, боевые дроны и реактор остаются отдельными задачами нативного переноса.

## Сборка

1. Возьмите Valve Source SDK 2013 Singleplayer на коммите `77567eb4bce8d7b6b7f73e929fcde3a331c0216e`. Для запуска нужен установленный в Steam **Source SDK Base 2013 Singleplayer** (243730). [Исходники Valve](https://github.com/ValveSoftware/source-sdk-2013/tree/77567eb4bce8d7b6b7f73e929fcde3a331c0216e)

2. Из этого каталога проверьте и примените патч. Он добавляет игровые исходники и заголовки к чистой копии SDK. Для копии с предыдущим патчем полёта подготовьте свежий checkout исходной ревизии Valve.

   ```sh
   python3 setup_hl2.py patch /path/to/source-sdk-2013 --check
   python3 setup_hl2.py patch /path/to/source-sdk-2013
   ```

3. Сгенерируйте штатные проекты Valve для HL2 и соберите `client` и `server` одной архитектуры. На Linux нужен 32-битный компилятор и библиотеки i386. Из каталога `src` SDK:

   ```sh
   ./devtools/bin/vpc /linux32 /hl2 +gamedlls /mksln abaddon_hl2
   make -f abaddon_hl2.mak CFG=release
   ```

   На Windows запустите штатный `src\creategameprojects.bat` и соберите проекты `client_hl2` и `server_hl2` в конфигурации Release для Win32.

   Облачная Linux-сборка использовала GCC 14 и sysroot i386. Для этого варианта понадобились две небольшие поправки к старой цепочке SDK. [Воспроизведение сборки с GCC 14](linux_gcc14_compat/README.md)

4. Разверните собранные библиотеки, `gameinfo.txt` и BSP в отдельной папке `sourcemods`. Для Linux передайте каталог с `client.so` и `server.so`, для Windows — с `client.dll` и `server.dll`.

   ```sh
   python3 setup_hl2.py deploy /path/to/source-sdk-2013/game/mod_hl2/bin /path/to/steamapps/sourcemods/abaddon_native
   ```

5. После перезапуска Steam откройте **Half-Life: Abaddon | Native Flight Lab**. Запустите из консоли `map d6_native_flightlab`.

## Первый прогон

```text
bind "z" "+alt1"
bind "x" "+alt2"
abaddon_flight
abaddon_flight_status
```

- WASD управляет тягой по курсу и боковым осям. Пробел и Ctrl поднимают и опускают по локальной вертикали. Z и X дают крен около 128°/с.
- В стартовом отсеке проверьте отсутствие ввода, полный крен и вращение мышью в перевёрнутом положении. Показания `abaddon_flight_status` включают координаты, скорость и углы.
- В шахте проверьте подъём через верхний обход, замедление при отпускании клавиш и скольжение по стене при косом заходе. Попытка пересечь сплошную стенку должна остановить движение поперёк неё.
- На ровной площадке выключите режим, проверьте обычные прыжок, приседание, оружие и уровень камеры. Повторите после перезагрузки карты. Ожидается `ABADDON_FLIGHT 0`.

Для проверки креплений включите `abaddon_mount_trace 1`. На открытом балконе удерживайте основную и дополнительную атаку вместе, затем добавьте верхнее и нижнее крепления. В строках `ABADDON_MOUNT shot` ожидаются разные крепления, последовательные номера выстрелов и чередование дул у каждого крепления. Проверьте вспышки при крене на бок и у боковой стены. Если между корпусом и стволом есть преграда, ожидается `ABADDON_MOUNT blocked` без номера выстрела у этого крепления. После выключения полёта верните штатное оружие в обычном игровом эпизоде и убедитесь, что выстрелы креплений прекращаются. Для обычной игры отключите трассировку командой `abaddon_mount_trace 0`.

Математика полёта, дульные точки и независимость креплений проверяются отдельными программами из этого каталога.

```sh
g++ -std=c++11 -Wall -Wextra -Werror tests/flight_math_test.cpp -o /tmp/abaddon-flight-test
/tmp/abaddon-flight-test
g++ -std=c++11 -Wall -Wextra -Werror tests/mounts_test.cpp -o /tmp/abaddon-mounts-test
/tmp/abaddon-mounts-test
```

Исходник геометрии лежит в `maps/d6_native_flightlab.vmf`. Для графической приёмки нужны запущенный клиент SDK Base и обе игровые библиотеки. Исполняемые файлы Valve и игровые VPK поставляет Steam.
